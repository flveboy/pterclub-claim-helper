## 一、目标页面结构

页面：`https://pterclub.net/getusertorrentlist.php?userid=<uid>&type=seeding`

NexusPHP 系模板。一个种子行（节选）：

```html
<tr>
  <td class="rowfollow nowrap"><a href="details.php?id=891957"><img ...></a></td>
  <td class="rowfollow"><a href="details.php?id=891957&hit=1">标题...</a></td>
  <td class="rowfollow nowrap">
    <a href="#" data-url="viewclaims.php?in_modal=yes&do_ajax=1&add_torrent_id=891957"
       class="claim-confirm">认领种子</a>
    <!-- 已认领时换成： -->
    <!-- <a href="#" data-url="viewclaims.php?in_modal=yes&do_ajax=1&del_torrent_id=900870"
             class="remove-confirm"><b><font color=red>取消认领</font></b></a> -->
  </td>
  <td class="rowfollow nowrap">9.63<br />GB</td>
  ...
</tr>
```

### 三个关键陷阱

**1. 认领按钮是唯一可靠的锚点**

不能用 `a[href*="details.php?id="]` 找行 —— 页面头部导航里有 `userdetails.php?id=27313`（会被 `details.php?id=` 匹配到）和「常用种子」的 `details.php?id=617936`，v1 就是因为这个多算了 5 行。

正确做法：找 `a.claim-confirm, a.remove-confirm`，每行恰好一个。

**2. 表头「大小」列是图标，文本为空**

```html
<td class="colhead"><img class="size" alt="size" title="大小"></td>
```

`textContent` 是空字符串。按文字找列必然失败，v1 的兜底逻辑因此抓到了「上传量」列，导致所有体积判断全错。

正确做法：`img[alt="size"], img.size, img[title="大小"]`。

**3. 体积单元格带 `<br />`**

`9.63<br />GB` 的 `textContent` 拼起来是 `9.63GB`（无空格），正则要写成 `/([\d.]+)\s*([KMGTP]?)i?B(?![A-Za-z])/i`。

### 列结构（9 列）

类型 / 标题 / 种子认领 / 大小 / 种子数 / 下载数 / 上传 / 下载 / 分享率

据此加了 `tr.cells.length < 6` 的过滤 —— 导航行、嵌套表格的外层 `<tr>` 都远小于 6 格。这是修复「本页多算 1 行」的关键：嵌套表格时外层 `<tr>` 的 `querySelector` 会穿透到内层按钮，同一个 ID 被数两次。

### 总数与分页

- 总数在标题里：`loongx 正在做种的种子 (共 130 个)` → 正则 `共\s*([\d,]+)\s*个`
- 分页参数：`?userid=X&type=seeding&page=N`，**`page=0` 时 URL 不带 page 参数**
- 每页 100 条，从分页链接文字 `101 - 126` 反推（`start - 1`）

## 二、认领接口

脚本发出的是：

```
GET viewclaims.php?do_ajax=1&add_torrent_id=<id>
GET viewclaims.php?do_ajax=1&del_torrent_id=<id>
```

即把行内按钮 `data-url` 里的 `in_modal=yes` 去掉。预期返回 `{"ret":0}`。

### 返回值三层兜底

| 顺序 | 判断 | 处理 |
| --- | --- | --- |
| 1 | 以 `{` / `[` 开头 | 解析 JSON，`ret === 0` 或 `success === true` 视为成功；否则取 `msg` 分类 |
| 2 | 返回 HTML 且含 `<form>` | 把表单字段抓出来，按原 method 重新提交一次 |
| 3 | 纯文本 | 命中「成功 / 已认领 / 已取消」判成功；命中「错误 / 失败 / 上限 / 权限」判失败 |

都判断不出来时返回 `{ unknown: true }`，日志记「无法判断返回：...」。**连续 3 个 unknown 会自动中断**，避免盲刷。

### 错误分类

`classify(msg)` 把错误消息分成三类：

- `skip` —— 已认领 / 重复 / 未认领 → 计入「跳过」，继续
- `stop` —— 上限 / 超出 / 权限 / 禁止 / ban → **立即中断**
- `fail` —— 其它 → 计入「失败」，继续

## 三、跨页读取与 WAF 兜底

`fetch` 抓分页时会做三重检查：

```js
if (res.redirected && /login\.php/i.test(res.url)) throw new Error('登录状态失效');
if (!res.ok) throw new Error(`HTTP ${res.status}`);
if (/Forbidden|Access Denied|cf-error/i.test(html) && !/claim-confirm|remove-confirm/.test(html))
  throw new Error('被站点防火墙拦截');
```

失败重试 1 次，仍失败则**改用隐藏 iframe**：

```js
const f = document.createElement('iframe');
f.src = pageUrl(p);
f.onload = () => resolve(f.contentDocument.cloneNode(true));
```

iframe 是真实页面导航，带完整浏览器请求头（含 Cookie、Sec-Fetch-Mode: navigate），能过大多数 WAF。测试里用 `?__blockfetch=1` 让 mock 对 `Sec-Fetch-Mode: cors` 的请求返回 403、放行 navigate，专门验证这条路径。

> 站点确实有 WAF：直接 `curl` 那个 URL 返回 `403 Forbidden: 0x2A7E1F29B9`。

## 四、执行队列

```
for each item:
  if aborted: break
  请求 → 分类 → 记录日志 → 标记行内按钮状态
  sleep(320 + random(0..220))
```

- **可中断**：`state.abort` 由「停止」按钮置位，当前请求跑完就退出
- **节流**：320ms 基础间隔 + 随机抖动，翻页 260ms
- **行内状态同步**：成功后调用 `markRow()`，把 `a.claim-confirm` 原地改成 `a.remove-confirm`（class、文字、`data-url` 一起改），页面和脚本状态始终一致。v2 早期只改 `display`，因为页面上原本只有一个 `<a>`，切换后什么也不变

上限保护：`CFG.maxPages = 40`，防止分页信息异常时无限翻页。

## 五、统计口径

早期版本有两个数字打架：面板显示「全站 100 个」、日志显示「全站 130 个」、页面标题写「共 130 个」。原因是面板显示的是**实际读到的行数**，而标题是**服务端声明的总数**，两者含义不同却混在一起显示。

现在的规则：

- 主体数字用页面声明的总数：`全站 130 个 · 2 页`
- 读到的行数与之不符时，红字追加 `已读 100`，一眼看出差多少
- 执行「一键认领 / 一键取消」前，如果两者不符，弹窗里明确警告并要求再次确认

## 六、测试设计

`test/mock_server.py` 起一个 NexusPHP 风格的做种列表，刻意还原了真实页面的坑：

- 130 个种子 / 2 页（第二页 30 个）
- 12 个已认领，按序号分散在两页
- 头部导航含 `userdetails.php?id=27313` 和「常用种子」的 `details.php?id=...`
- 表头用 `<img class="size" alt="size">`
- 体积覆盖边界：`100.0 MB`（不应认领）、`96.5 MB`、`62.4 MB`、`0.00 KB`、`30 MB`
- 认领接口返回 JSON，并按 ID 记录请求，供断言比对

`test/run_test.js` 用 puppeteer 注入脚本，20 项断言覆盖：跨页扫描、体积边界、已认领跳过、请求数量精确匹配、按钮翻面、多选只处理勾选行、退出多选还原、WAF 拦截下 iframe 兜底。

**踩过的坑**：等待「完成」的正则 `/完成：/` 会误中日志里的「扫描完成：」，导致只跑了 1 个请求就断言；改成等 `/成功 \d+ · 跳过 \d+/`。同理，等扫描完成要等「扫描完成：」，不能等统计里出现「全站」二字（未扫完也有这两个字）。

## 七、已知限制

**1. 接口返回格式未在真实站点验证**

`viewclaims.php?do_ajax=1&add_torrent_id=X` 是否直接生效（去掉 `in_modal=yes` 之后），需要登录态才能确认，开发时只能靠公开资料和页面里的 `data-url` 推断。因此做了三层兜底 + 自动中断。如果实测时日志出现大量「无法判断返回」，把那段内容贴出来就能补上判断。

**2. 只适配 pterclub 这一套模板**

`@match` 只写了 `pterclub.net`。同系 NexusPHP 站点结构大同小异，改 `@match` 一般能用，但表头图标和按钮 class 可能不同，需要对着 DOM 调 `sizeCol()` 和 `parseDoc()`。

**3. 认领上限依赖服务端报错**

脚本不知道你的账号上限是多少，只能等服务端返回「上限」类错误再中断。也就是说上限那一刻会多打一个请求。

**4. 全站扫描的请求量**

2 页 = 2 个请求，问题不大；种子数上千（10+ 页）时会连续打十几个请求，间隔 260ms。如果站点对翻页有频率限制，把 `CFG.pageDelayMs` 调大。

## 八、版本历史

### v2.1.0

- 修复分页 `fetch` 被 WAF 拦后静默返回空页 → 检查 `res.ok` + 内容特征，失败改用 iframe
- 修复嵌套表格导致同一行被计两次 → `tr.cells.length < 6` 过滤 + 按 ID 去重
- 统一统计口径：以页面「共 N 个」为准，读不全时红字提示 + 执行前弹窗警告
- 日志改为逐页报告：`第 2 页：30 个` / `扫描完成：2 页，读到 130 个`
- 测试扩到 20 项，新增 WAF 拦截场景

按真实页面源码重写，修掉 v1 的四个 bug：

| bug | 原因 |
| --- | --- |
| 行数多 5 个 | `details.php?id=` 把头部导航和「常用种子」也算进去了 |
| 体积全错 | 表头是 `<img alt="size">`，文本为空，兜底抓到了「上传量」 |
| 已认领只显示 3 个 | 真实按钮是 `a.claim-confirm / a.remove-confirm`，不是 `data-action` |
| 认领全部失败 | 接口是 `viewclaims.php?do_ajax=1`，不是不存在的 `ajax.php` |

同时把「一键认领 / 一键取消」改为全站范围，「多选」保持本页。
